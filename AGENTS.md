# Instrucciones del proyecto

Trabajar por etapas pequeñas y esperar la revisión del usuario antes de iniciar la etapa siguiente.

## Uso eficiente del contexto

- Leer solamente los archivos necesarios para la tarea actual.
- No repetir lecturas extensas de archivos ya revisados, salvo que hayan cambiado.
- Limitar la salida de comandos y registros a la información necesaria para diagnosticar o verificar.
- Reutilizar las decisiones, maquetas y resúmenes ya guardados en el proyecto.
- Mantener las respuestas breves: resultado, forma de probarlo y pendientes relevantes.

## Implementación y pruebas

- Hacer cambios acotados al objetivo de la etapa y conservar el trabajo existente del usuario.
- Ejecutar primero las pruebas directamente relacionadas con el cambio.
- Ampliar las pruebas solamente si el riesgo, un error o una dependencia lo justifica.
- Reservar la revisión integral de todas las funciones para el cierre de cada etapa importante o del proyecto.
- No generar nuevas maquetas ni consultar Figma si el diseño aprobado alcanza para implementar el cambio.

## Entrega

- Indicar qué cambió, dónde quedó y cómo puede probarlo el usuario.
- Registrar decisiones que deban sobrevivir a otra conversación en un archivo breve del proyecto.
- No avanzar automáticamente a la etapa siguiente después de entregar una etapa para revisión.
